Генерация разборов Veluna Техническое задание для разработчика · как поставить генерацию «текст → дизайн → диаграммы» на поток через Claude API

Главная идея архитектуры. Модель (LLM) НЕ рисует HTML руками — это ненадёжно на длинных разборах. Модель отдаёт только данные в строгом JSON, а готовый HTML-шаблон на нашей стороне детерминированно превращает эти данные в свёрстанную страницу с диаграммами. Дизайн тогда идентичен на каждом разборе, а не «как повезёт».

Вход
Имя, дата, пол, время (опц.), место (опц.)
→
LLM Пасс 1
Промт A07 + правило «отдай JSON». Claude возвращает структуру: обложка, 11 блоков, 10 значений сфер, границы циклов
→
CODE Пасс 2
Наш рендер подставляет JSON в HTML-шаблон + SVG-диаграммы. Готовый файл / PDF

2Модель и SDK

  • Модель: claude-opus-4-8 (лучшее качество текста; для экономии на объёме — claude-sonnet-5).
  • SDK: официальный Anthropic — Python (pip install anthropic) или Node (npm i @anthropic-ai/sdk).
  • Ключ: env-переменная ANTHROPIC_API_KEY. Никогда не хардкодить в коде.
  • Structured output: через client.messages.parse() (Python + Pydantic) или output_config.format — гарантирует валидный JSON по нашей схеме.
  • Стриминг обязателен: разбор длинный (5–7к слов). Ставим max_tokens=32000+ и используем стрим, иначе запрос упрётся в таймаут.
  • Кэш-экономия: системный промт A07 большой и одинаковый — вешаем на него cache_control: ephemeral. Каждый следующий разбор дешевле на ~90% по системной части.

3JSON-контракт (что модель обязана вернуть)

Это единственный «интерфейс» между LLM и вёрсткой. Разработчик валидирует ответ по этой схеме; вёрстка читает только эти поля.

    {"key":"health",       "label":"Здоровье",        "value":6},
    {"key":"finance",      "label":"Финансы",         "value":6},
    {"key":"career",       "label":"Карьера и дело",  "value":7},
    {"key":"relations",    "label":"Отношения",       "value":5},
    {"key":"circle",       "label":"Окружение",       "value":8},

Важно про данные: место рождения опционально. Если его нет — модель по правилу A07 не считает Асцендент и «дизайн человека» и не выдумывает их. На JSON это не влияет по форме, но текст будет честным. Числа возраста/годов в диаграммах — разрешены; «голые магические числа» систем (проценты стихий, номер типа) — запрещены и в JSON их нет.

3.1Правило-обёртка к промту (добавить к A07)

A07 сейчас пишет текст. Для пасса-1 добавляем в конец системного промта короткую инструкцию вывода:

Сгенерируй ПОЛНЫЙ разбор и верни его СТРОГО одним JSON-объектом
по заданной схеме. Никакого текста вне JSON. Правила разбора (стоп-слова,
скрытие систем, дуга, якорные фразы, поведенческие формулировки) —
соблюдать внутри полей paragraphs/anchor/bridge. Значения spheres — целые
0..10, отражают силу сфер по тексту. cycles/agePoints — из расчётов.

4Пример кода (Python)

import anthropic, json
from pydantic import BaseModel

# 1) описываем схему (Pydantic) — Sphere, Block, Reading …
class Reading(BaseModel):
    cover: dict; spheres: list; cycles: dict
    agePoints: list; peakAge: str; blocks: list

client = anthropic.Anthropic()   # ключ из ANTHROPIC_API_KEY

SYSTEM = open("A07_full_reading_v12.md", encoding="utf-8").read() + WRAPPER

# 2) генерация → строгий JSON (стрим, т.к. ответ большой)
with client.messages.stream(
    model="claude-opus-4-8",
    max_tokens=48000,
    thinking={"type":"adaptive"},
    system=[{"type":"text","text":SYSTEM,
             "cache_control":{"type":"ephemeral"}}],
    output_config={"format":{"type":"json_schema","schema":Reading.model_json_schema()}},
    messages=[{"role":"user",
        "content":"Имя: Аблай · дата: 14.02.1998 · пол: м · время: 17:00 · место: —"}],
) as stream:
    msg = stream.get_final_message()

data = json.loads(next(b.text for b in msg.content if b.type=="text"))

# 3) рендер: подставляем data в HTML-шаблон + SVG (наш код, без LLM)
html = render_template(data)          # см. п.5
open("razbor.html","w",encoding="utf-8").write(html)

render_template — обычная шаблонизация (Jinja2 / string.Template / JS-темплейт). Берёт Аблай_разбор_ПРЕМИУМ.html, оставляет CSS/структуру как есть, а тексты и числа подставляет из data.

5Маппинг «блок → диаграмма» (для рендера)

Все SVG уже готовы в эталонном файле. Рендер по полю diagram вставляет нужный компонент и заполняет его числами из JSON. Не более 1 диаграммы на блок.

БлокdiagramДанные из JSON
Введениеarc—(статичная дуга)
Карта сферradar ⭐spheres[].value → координаты полигона
Ядроtriad—
Талантыforcesширины 3 полос (можно фикс.)
Деньгиmoneyокна года (весна/осень/лето)
Блокиaxis—
Циклыlifecycles.b1/b2/b3, challenge
ВозрастagesagePoints[], peakAge
Прогнозyearкварталы + развилка
Горизонтnullбез диаграммы
Миссияmap ⭐карта 12 слоёв (статичная)
⭐ Радар — единственная диаграмма с реальным пересчётом координат. Формула вершины: центр (250,250), радиус r = value/10 × 200, угол -90° + i×36°. Код-генератор points — 8 строк; можно вынести в утилиту radarPolygon(values).

6Опция: генерация по главам (если один запрос тяжёл)

Если разбор целиком в одном запросе получается слишком большим — генерировать блоки пачками (например: обложка+сферы+ядро → таланты+деньги+любовь → блоки+циклы → возраст+прогноз+горизонт+миссия), сохраняя историю диалога, затем собрать общий JSON. Системный промт (A07) при этом кэшируется и переиспользуется — дёшево.

7QA-чек перед отдачей клиенту

  • JSON проходит валидацию схемы; 11 блоков, 10 сфер, значения 0..10.
  • В текстах нет стоп-слов и названий систем (простой словарный фильтр по списку из A07).
  • Радар присутствует; карта 12 слоёв присутствует; ≤1 диаграммы на блок.
  • Файл открывается офлайн; печать в PDF (обложка на страницу, главы с новой страницы).
  • Мобилка: колонка не ломается, SVG тянутся по ширине (viewBox + width:100%).
  • Нет места рождения → в тексте нет выдуманных Асцендента/«дизайна» (спот-чек).

Короткое резюме для разработчика

Есть промт A07 (генерация) и эталонный HTML Аблай_разбор_ПРЕМИУМ.html (вёрстка). Задача: (1) обернуть A07 инструкцией «верни JSON по схеме из п.3», (2) вызвать claude-opus-4-8 со structured output + стрим + кэш системного промта, (3) написать render_template(data), который подставляет JSON в шаблон и заполняет радар по формуле из п.5. LLM отвечает за содержание, шаблон — за дизайн. Диаграммы уже нарисованы.
